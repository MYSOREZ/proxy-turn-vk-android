# qWDTT-HY2 — сборка с Hysteria2 вместо WireGuard

Форк qWDTT **1.4.4** (upstream: SpaceNeuroX/proxy-turn-vk-android, коммит `a296c57`),
в котором внутрь TURN-туннеля вместо WireGuard едет **Hysteria2 (QUIC)**.

Ставится и работает **параллельно** с оригинальным qWDTT — и на телефоне,
и на сервере. Оригинал удалять не нужно.

## Зачем

Транспорт до VPS (VK TURN + DTLS + RTP-обфускация) остаётся тем же самым.
Меняется только то, что едет внутри:

```
было:   WireGuard → 127.0.0.1:<порт> → TURN → VPS → встроенный WireGuard
стало:  Hysteria2 → 127.0.0.1:<порт> → TURN → VPS → сервер Hysteria2
```

WireGuard — это L3-туннель без ретрансмита: потери TURN-релея проходят
насквозь, и разгребает их TCP внутри туннеля, схлопывая окно. QUIC у
Hysteria2 восстанавливает потери сам и имеет собственный контроль
перегрузки, поэтому внутренний TCP этих потерь не видит.

## Что именно изменено относительно 1.4.4

| Файл | Изменение |
|---|---|
| `server/main.go` | флаг `-forward <addr>` — отдавать расшифрованный трафик на произвольный локальный UDP-порт вместо встроенного WG; флаг `-wg-iface` |
| `server/core.go` | `wgIfaceName` из константы стал переменной (иначе второй экземпляр сервера сносил бы `wdtt0` первого) |
| `go_client/hysteria.go` | новый: клиент Hysteria2 + локальный SOCKS5 поверх него |
| `go_client/main.go` | `-mode hysteria`, флаги `-hy2-pass/-hy2-sni/-hy2-insecure/-hy2-up/-hy2-down` |
| `app/.../TunnelManager.kt` | третий режим (кнопка **HY2**) шлёт ядру `-mode hysteria` |
| `app/build.gradle.kts` | `applicationId = net.qwdtt.hy2`, versionName `1.4.4-hy2` |
| `AndroidManifest.xml`, `shortcuts.xml`, `TunnelWidgetProvider.kt` | свой label и свой broadcast-action, чтобы не пересекаться с оригиналом |
| `app/src/main/assets/deploy.sh` | развёрнут на свои порты/пути/юниты + ставит Hysteria2; контракт с приложением сохранён |
| `app/.../DeployTab.kt` | установка/удаление по SSH переведены на идентификаторы клона (иначе сносили оригинал) |

Путь данных на сервере изначально был обычным UDP-релеем
(`net.Dial("udp", wgEndpoint)`), протокол внутри он не разбирал — поэтому
подмена WireGuard на QUIC не потребовала менять сам транспорт.

## Разделение с оригиналом (ничего не пересекается)

| параметр | оригинал qWDTT | эта сборка |
|---|---|---|
| Android applicationId | `net.qwdtt.client` | `net.qwdtt.hy2` |
| имя в лаунчере | qWDTT | qWDTT-HY2 |
| DTLS порт | 56000 | 56100 |
| внутренний WG порт | 56001 | 56101 (не используется) |
| admin API | 56002 | 56102 |
| Hysteria2 | — | 56143 (только localhost) |
| TUN-интерфейс | `wdtt0` | `wdtthy0` |
| каталог конфигов | `/etc/wdtt` | `/etc/wdtt-hy2` |
| systemd | `wdtt.service` | `wdtt-hy2.service`, `hysteria-hy2.service` |
| бинарник | `wdtt-server` | `wdtt-hy2-server` |
| метка iptables | `WDTT_MANAGED` | `WDTT_HY2_MANAGED` |

Все порты переопределяются переменными `WDTT_HY2_*`.

## Установка

### Сервер — кнопкой «Установить» в приложении

Так же, как в оригинале: вкладка **Серверы** → IP, логин, SSH-пароль/ключ →
**Установить**. Приложение само зальёт по SSH свой скрипт и свой бинарник и
всё настроит, включая Hysteria2.

Оригинальная установка при этом не затрагивается — всё разведено (см.
таблицу выше). Кнопка **Удалить** тоже убирает только эту сборку.

Проверить на сервере, что оба живы:

```bash
systemctl status wdtt          # оригинал
systemctl status wdtt-hy2 hysteria-hy2   # эта сборка
```

### Телефон

Поставить `app-arm64-v8a-debug.apk` рядом с оригиналом — package другой,
поэтому оригинал не перезапишется. В приложении:

* **IP сервера** — просто IP VPS (порт 56100 подставится сам)
* **пароль** — пароль подключения; он же используется как пароль Hysteria2
* **режим** — кнопка **HY2**
* VK-хеш — как обычно

## BBR или Brutal

По умолчанию Hysteria2 работает на **BBR**. Brutal (шлёт с заданной
скоростью и не считает потери сигналом перегрузки) включается заданием
полосы на клиенте:

```
-hy2-up 20 -hy2-down 50      # Мбит/с
```

Сейчас эти флаги приложение не выставляет — если BBR окажется хуже, их
надо прокинуть в `TunnelManager.kt` рядом с `-hy2-pass`.

## Важно: что НЕ проверено

Код собирается (сервер, клиент под linux/amd64 и под все Android ABI) и APK
устанавливается, **но вживую эта связка не тестировалась**: не было ни VPS,
ни телефона, ни VK-хеша. В частности не проверялись:

* реальное прохождение QUIC через TURN-релей VK;
* поведение при потерях и сама гипотеза про прирост скорости;
* работа режима HY2 в интерфейсе приложения.

Режим **HY2 отдаёт локальный SOCKS5 и не поднимает системный VPN** (так
устроен третий режим и в оригинале). Для замера скорости это подходит,
для «весь трафик телефона» — ещё нет.
